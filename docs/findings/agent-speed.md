# Скорость агентов: журнал наблюдений

Куда уходит время у живых агентов — на мысль модели или на инструмент, — и
что меняет темп. Сырые снимки раз в 3 минуты: `~/.cckit/bench/speed/*.jsonl`,
сэмплер там же (`sampler.py`). Всё ниже — **наблюдения**, по одному случаю,
пока не повторено.

## 2026-09-24 03:15 — boomzi-assistant: медленный старт, потом веер

Сессия `5764772b`, вкладка, `claude-opus-5-5[1m]`, effort max, спавн разрешён,
Bash запрещён. Задание — записать разбор VS Code основного агента в досье.

| мин | что происходило |
|---|---|
| 0.0–1.7 | ждёт задания (так и велено) |
| 1.7 | приходит бриф от основного агента, 11 859 знаков |
| 1.76–1.89 | 9 ориентировочных чтений за 8 секунд: INDEX, README, досье, `specs.md` (62 КБ, дважды — не влез одним куском) |
| 1.89–3.22 | **80 секунд тишины** — план после брифа и 62 КБ specs |
| 3.22–6.79 | 9 субагентов, по одному каждые ~20 с — каждый вызов Agent это длинный бриф субагенту, то есть вывод |
| 6.79 → | 12 субагентов работают одновременно: 65, 70, 85, 86 вызовов у крупных; сам ассистент — 26 вызовов |

Что ускорило: **веер субагентов**. Сам ассистент почти ничего не читает — он
раздаёт области и ждёт.

Что было медленным:
1. 80 с планирования над 62 КБ `specs.md`. Большой общий файл читается целиком
   прежде, чем что-то раздать.
2. Раздача последовательная: 9 × ~20 с ≈ 3 минуты только на написание брифов.
   Это цена правила «бриф наружу полный» — она платится выводом.
3. **Обход запрета Bash.** Ассистент попросил Bash через ToolSearch, не получил и
   отдал чтение git субагентам — а у них тот же запрет: один из них сделал ноль
   вызовов. Ограда держит и на субагентах (хорошо), но стоит времени (плохо).

### 03:24 — тот же прогон, минута ~9

13 субагентов, все писали в последнюю минуту, 511 вызовов на всех. Сам
ассистент — последний ход 24 с назад: раздал и ждёт.

**Четыре из тринадцати — ради git** («git state capture» 12 вызовов, «read-only
git commands» 8, «git status/diff» 1, «git log» 1). Им нужен `sha` для обязательной
строки «собрано … на коммите <sha>». Bash закрыт и ассистенту, и его субагентам
(запрет наследуется), поэтому то, что даёт одна команда `git log -1; git status`,
собирается четырьмя агентами, читающими `.git/` руками.

Гипотеза для карточек, не проверена: узкая выдача только на чтение git —
`Bash(git log*)`, `Bash(git status*)`, `Bash(git rev-parse*)` — заменила бы
четырёх агентов одной командой и не открыла бы шелл. Правило формата, которое
требует `sha`, и ограда, которая не даёт его прочесть, тянут в разные стороны.

## 2026-09-24 03:55 — почему субагенты быстрее основных агентов и ассистентов

**Наблюдение**, по одной сессии каждого вида. Мышление на ход считается только по ходам,
где поле `thinking_tokens` есть в стенограмме: у субагентов оно есть меньше чем у
половины ходов, и первый подсчёт, считавший отсутствие нулём, дал ложный «0».

| | вызовов/мин | пауза перед ходом (мед.) | мышление на ход (мед.) | контекст на старте |
|---|---|---|---|---|
| основной агент 9ffe957a | 1.3 | 7.1 с | 911 | 48k |
| старая рука 146c535f | 2.4 | 3.3 с | 186 | 40k |
| ассистент boomzi 5764772b | 3.3 | 1.8 с | 210 | 25k |
| субагенты основного (5) | 9.7 | 2.3 с | 181 | 15k |
| субагенты ассистента (18) | 11.0 | 1.8 с | 112 | 17k |

Догадки владельца — «потому что у них нету claude, и потому что им дают четкую задачу»:

1. **Нет CLAUDE.md — неверно.** `CLAUDE.md` зовущей сессии приходит каждому субагенту
   (измерено нонсами, см. `subagents.md`). У субагента нет остального: разговора, промпта
   роли, памяти, контекста хука старта — отсюда стартовый контекст 15–17k против 25–48k.
2. **Чёткая задача — согласуется.** Субагент думает на ход 112–181 токен, основной агент — 911:
   основной решает, *что* делать, субагент только *делает*.
3. **Субагент никогда не ждёт** — ни человека, ни одобрений, ни своих субагентов. Вызовы в
   минуту у основного агента занижены простоями; как «медлительность модели» их читать нельзя.

## 2026-09-24 01:26–01:53 UTC — сэмплер, 30 минут, основной агент и boomzi-assistant

Снимки раз в 3 минуты, `~/.cckit/bench/speed/2026-09-24.jsonl`. Время мысли — от
результата инструмента (или промпта) до следующего хода модели; время инструмента — от
вызова до результата. Ожидание человека не считается.

1. **Время уходит на модель, не на инструменты.** Доля мысли в занятом времени — от 0.65
   до 0.99 во всех окнах у всех агентов, почти везде выше 0.8. Инструменты стоят секунды.
   Ускорять надо **число ходов модели** (одна команда Bash вместо десяти Grep, веер вместо
   очереди), а не сами инструменты. *Измерено.*
2. **Естественный опыт с Bash у субагентов.** До открытия Bash субагенты ассистента
   искали через Grep (338 вызовов за окно 01:26, 74 за 01:29); после открытия (~01:33)
   новые субагенты перешли на Bash (9, 23, 9 вызовов в окнах 01:35–01:41). Фаза задачи
   сменилась тогда же — *наблюдение*, не опыт.
3. **Сжатие контекста.** Контекст основного агента рос до 456k и в окне 01:53 упал до
   142k; в том же окне темп — 6 вызовов/мин против 1–3 до того. Одно окно — *наблюдение*.
4. **Веер в цифрах:** субагенты ассистента в первом окне — 374 вызова за 3 минуты
   (124/мин на всех), сам ассистент — 4.
