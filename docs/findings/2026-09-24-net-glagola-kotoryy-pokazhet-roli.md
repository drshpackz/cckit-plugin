# Нет глагола «покажи роли»: список ролей выдаётся только в тексте ошибки

**Статус:** измерено (чтение кода, все точки вызова пересчитаны)
**Где:** bin/cckit_assistant.py:603 (`known_roles`), единственный вызов — :600 внутри `die()`; main():1025-1065
**Класс:** обещание (глагол, которого нет) + дорога в обход

## Как воспроизвести

Все глаголы CLI — `main()`, строки 1045-1065:
`run`, `install`, `list`, `where`, `show`, `grant`, `revoke`, `owner-rule`,
`reset`, `tree`. **Десять.** Ни один не отвечает на вопрос «какие роли я
вообще могу поставить».

`list` перечисляет **экземпляры**, а не роли:

```python
def cmd_list(argv):
    items = instances()            # bin/cckit_assistant.py:763
```

`instances()` (:742) читает `~/.cckit/assistants/*/instance.json`. У человека,
только что поставившего плагин, этот каталог пуст, и `list --all` печатает
«для этого проекта ассистентов нет».

Функция, которая знает ответ, существует:

```python
def known_roles():                 # :603
    names = []
    for _, root in role_roots():   # ваша библиотека + assistants/ плагина
```

Точек вызова у неё ровно одна, и та — в сообщении о смерти:

```
rg -n 'known_roles' bin/ skills/ hooks/ tests/
bin/cckit_assistant.py:600:        % (role, "\n".join(tried), ", ".join(known_roles()) or "ничего"))
bin/cckit_assistant.py:603:def known_roles():
```

Строка 600 — внутри `die()` в `role_dir()`. Значит **единственный** способ
узнать, что плагин везёт роль `design-scout`, — попросить роль, которой нет,
и прочитать список в отказе:

```
python3 bin/cckit_assistant.py install нет-такой --project .
роль «нет-такой» не найдена. Искал: ...
  что есть: design-scout, cckit-smith
```

При этом `skills/find-agent/SKILL.md:10` посылает человека именно за этим —
и в другое место:

> 1. **Installed here** — `cckit assistant list --all`. A role already in the
>    library installs into a new project in one command.

Скилл обещает, что `list --all` покажет **роли** («a role already in the
library»). Код показывает экземпляры. У чужого человека на первом шаге их
ноль, и скилл уводит его на шаг 2 — «поищи на GitHub» — мимо роли, которая
лежит у него на диске внутри плагина.

## Чем доказано

Мутацию не прогонял: в моей ограде нет Bash. Доказательство — исчерпывающий
перебор: множество глаголов `main()` (10 штук, выписаны выше) и множество
точек вызова `known_roles` (1 штука, в `die`). Оба множества полные, не
выборка.

Почему существующие ворота это не ловят: `tests/test_cold_path.py` сверяет
**обещанное** с **существующим** в обе стороны (:71 и :77). Глагол, которого
нет ни там, ни там, проходит обе проверки — симметрия не спасает от общей
слепоты. Это тот же класс, что дал отсутствие `run`; тогда его нашли не
тестом, а вопросом «что человек вообще делает с этой вещью».

Тест, красный на `HEAD`, — не про регулярное выражение, а про поведение:

```python
def test_a_stranger_can_discover_what_roles_exist(self):
    with Sandbox() as sb:
        rc, out = call(["roles"])          # глагола нет → die("нет команды: roles")
        self.assertEqual(rc, 0, out)
        self.assertIn("design-scout", out)
```

На `HEAD` падает на `main()`: `die("нет команды: roles")` → `SystemExit`,
`rc != 0`, сообщение «нет команды: roles».

## Что предлагаю

Глагол `roles` — десять строк, использующих уже написанную `known_roles()`:

```python
    if cmd == "roles":
        return cmd_roles(rest)
```

```python
def cmd_roles(argv):
    """Что можно поставить. Раньше этот список существовал только в тексте
    отказа: узнать про роль можно было, лишь попросив несуществующую."""
    for label, root in role_roots():
        names = [n for n in sorted(os.listdir(root))
                 if os.path.isfile(os.path.join(root, n, "card.yaml"))] \
                if os.path.isdir(root) else []
        print("%s: %s" % (label, ", ".join(names) or "пусто"))
    return 0
```

и строку в справку `main()` (:1031) — глагол, которого нет в справке, для
человека не существует, это уже записано там же в комментарии.

Плюс правка `skills/find-agent/SKILL.md:10`: шаг «Installed here» должен
звать глагол, показывающий роли, а не экземпляры. Тогда
`tests/test_cold_path.py` подхватит новый глагол сам — README и скиллы у него
источник обещаний.

Почему не «дописать в README список ролей»: список рядом со свойством
расходится с ним при первой же новой роли. `roles` читает диск.

## Чего это НЕ закрывает

- Не закрывает **обратную** сторону: роль, лежащую в библиотеке, но негодную
  (битая `card.yaml`, роль с абсолютными путями чужой машины). `roles` покажет
  её как равную; судить роль по-прежнему предлагается глазами
  (`skills/find-agent/SKILL.md:16-27`).
- Не закрывает вопрос, **должна ли** `cckit-smith` быть в этом списке видна
  чужому человеку — см. `2026-09-24-v-biblioteke-dve-roli-a-obeschana-odna.md`.
- `cmd_roles` выше я не прогонял: Bash в ограде нет. Это предложение кода, а
  не проверенная правка.
