# Обёртка `cckit-assistant` зовёт `~/cckit-plugin` — рабочую копию, а не установленный плагин

**Статус:** измерено (по коду обёртки); где лежит установленный плагин — не подтверждено
**Где:** ~/.cckit/current/bin/cckit-assistant:8; ~/.cckit/current/bin/cckit-package (0 упоминаний плагина)
**Класс:** дорога в обход + среда

## Как воспроизвести

```
IMPL="${CCKIT_ASSISTANT_IMPL:-$HOME/cckit-plugin/bin/cckit_assistant.py}"
```

`~/cckit-plugin` — git-checkout владельца. То, что стоит через
`/plugin install cckit@cckit-plugin`, лежит в кеше плагинов под `~/.claude/`
(точный путь мне закрыт: Glob по `~/.claude` отказал). Значит `cckit
assistant` у владельца исполняет **незакоммиченное и неопубликованное**, а
у всех остальных — ничего: `exit 127`.

Чужой человек с семьёй (`cckit deploy HOST`) получает обёртку, потому что
она в `bin/` пакета, но не получает плагин: grep по `cckit-package` на
`cckit-plugin|cckit_assistant|.claude/plugins` — **0 совпадений**. На
свежем хосте `cckit assistant list` → «нет реализации по пути
/home/x/cckit-plugin/bin/cckit_assistant.py». Чужой без семьи теряет глагол
целиком (см. `2026-09-24-readme-zovet-binarnik-kotorogo-net.md`).

## Чем доказано

LEARNED, «Вторая машина»: первый прогон там показал «нет команды: roles»,
потому что глагол был закоммичен и не отправлен. Обёртка — механизм, который
делает это расхождение **невидимым дома**: всё, что владелец проверяет через
`cckit assistant`, проверяется на рабочей копии. Тест-мутация здесь один:
`CCKIT_ASSISTANT_IMPL=/nonexistent cckit assistant list` → 127 — обёртка
не ищет плагин нигде, кроме одного пути.

## Что предлагаю

Порядок поиска в обёртке: `$CCKIT_ASSISTANT_IMPL` → установленный плагин
(`$CLAUDE_PLUGIN_ROOT`, затем `~/.claude/plugins/**/cckit/bin/cckit_assistant.py`)
→ `~/cckit-plugin` **последним и с предупреждением в stderr** «исполняется
рабочая копия, не плагин». Так дом перестаёт быть дорогой в обход.

## Чего это НЕ закрывает

- Путь установленного плагина не подтверждён на диске — правка выше
  называет его по памяти о раскладке Claude Code, это надо проверить.
- Не отвечает, должен ли `cckit deploy` вообще везти плагин: это решение
  владельца, не находка.
