# «a linter enforces it» — линтер есть, но его не зовёт ни один код

**Статус:** измерено (все точки вызова пересчитаны по дереву вне docs/ и .git)
**Где:** README.md:86-88 · bin/cckit_learned.py:106 · ни одного вызова в bin/, skills/, hooks/, dev.sh
**Класс:** обещание + проверка, которая не кусается

## Как воспроизвести

README:

> Every record in `LEARNED.md` carries how well it is known — `измерено`,
> `наблюдение`, `гипотеза`, `слово владельца` — and a linter enforces it.

Кто зовёт линтер:

```
rg -n 'cckit_learned' --glob '!{docs,.git}/**' .
bin/cckit_learned.py:106:        sys.stderr.write("нужен путь: cckit_learned.py <LEARNED.md> [ещё...]\n")
tests/test_learned.py:22:import cckit_learned as learned  # noqa: E402
```

**Ноль производственных вызовов.** Имени `cckit_learned` нет:

- в `bin/cckit_assistant.py` — `install`, `run`, `reset` его не трогают;
  `reset` (:911) переписывает `LEARNED.md` шаблоном и не проверяет ничего;
- в `dev.sh` — `check` перебирает JSON-манифесты, синтаксис всех `.py`,
  frontmatter скиллов, хуки и жёсткие пути; строки про `LEARNED` там нет;
- в `hooks/session-start` — он только печатает текст скилла;
- в `skills/**` — ни один скилл о линтере не упоминает.

То есть слово «enforces» не обеспечено ничем: файл проверяется ровно тогда,
когда человек, уже знающий о существовании `bin/cckit_learned.py`, наберёт
`python3 bin/cckit_learned.py <путь>` руками. Глагола в CLI для этого нет
(`main()`, :1045-1065, десять глаголов, ни одного про `LEARNED`).

Цена ровно та, что назвал автор самого линтера
(`bin/cckit_learned.py:4-5`): «без статуса догадка одной сессии через месяц
читается ровно как измеренный факт — и ассистент, который её прочтёт, тоже не
отличит одно от другого». Ассистент дописывает `LEARNED.md` сам, каждую
сессию; его `CLAUDE.md` тянет файл через `@LEARNED.md`
(`bin/cckit_assistant.py:528`). Никто между записью и чтением не стоит.

## Чем доказано

Мутацию не прогонял — в моей ограде нет Bash. Доказательство исчерпывающее по
построению: поиск имени модуля по всему дереву вне `docs/` и `.git` даёт две
строки, обе — сам линтер и его юнит-тест. Третьей нет.

Тест, красный на `HEAD`:

```python
def test_the_learned_linter_is_actually_wired_somewhere(self):
    # Линтер, которого никто не зовёт, зелен всегда — и enforces ничего.
    hits = []
    for rel in ("dev.sh", "bin/cckit_assistant.py"):
        hits += ["cckit_learned" in open(os.path.join(PLUGIN, rel), encoding="utf-8").read()]
    self.assertTrue(any(hits), "README обещает линтер, но его не зовёт ни dev.sh, ни CLI")
```

На `HEAD` `hits == [False, False]` → падает с этим сообщением.

## Что предлагаю

Одно из двух, и первое дешевле:

1. **Ворота.** В `dev.sh cmd_check`, рядом с проверкой скиллов, — прогон
   линтера по `LEARNED.md` репозитория и по шаблону `LEARNED_MD`:

```bash
    python3 "$ROOT/bin/cckit_learned.py" "$ROOT/LEARNED.md" \
        && good "LEARNED.md — статусы на месте" || bad "LEARNED.md — запись без статуса"
```

   Это делает слово «enforces» верным хотя бы для того, что публикуется.

2. **Глагол.** `cckit assistant lint <экземпляр>` (и вызов того же линтера
   из `run` после возврата ребёнка) — тогда обещание становится верным для
   пользователя, а не только для репозитория. Дороже: новый глагол обязан
   попасть в справку и, следовательно, в `tests/test_cold_path.py`.

Пока не сделано ни то, ни другое, честная правка README — одна строка:
«…and `bin/cckit_learned.py` checks it when you run it» вместо «a linter
enforces it». Заявление без замера — мнение; здесь замер даже не заказан.

## Чего это НЕ закрывает

- Не отвечает, **правильно** ли линтер разбирает записи: `tests/test_learned.py`
  содержит 16 тестов, я их не читал и не прогонял. Находка про то, что его
  никто не зовёт, а не про то, что он врёт.
- Не закрывает `LEARNED.md` **экземпляров** в `~/.cckit/assistants/**`: даже
  вариант 1 проверяет только файл репозитория. Файлы живых ассистентов — там,
  где догадка и превращается в «факт», — остаются непроверенными.
- Вариант 2 я не прогонял и кода для него не предлагаю: он требует решения
  про справку и про поведение `run` при красном линтере (ронять? предупреждать?),
  а это решение владельца.
